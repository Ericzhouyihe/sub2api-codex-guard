## Irreversible Migration — Export Before Updating

Upstream removed the「用户流量」feature. `backend/migrations/398_drop_user_traffic.sql` runs when the
new image starts:

```sql
DROP TABLE IF EXISTS user_traffic_events, user_traffic_hourly;
```

The built-in update channel takes no data snapshot (`docs/UPGRADING.md` 1.1 and 10.3), and rolling
the image back does not restore dropped rows. If those records are needed, export them on the server
**before** clicking “立即更新镜像”:

```bash
# 先看两张表里有没有数据
docker exec -i sub2api-postgres psql -U sub2api -d sub2api -Atc \
  "select 'events='||count(*) from user_traffic_events; select 'hourly='||count(*) from user_traffic_hourly;"

# 需要保留时导出
mkdir -p /root/backups
docker exec sub2api-postgres pg_dump -U sub2api -d sub2api -Fc \
  -t user_traffic_events -t user_traffic_hourly \
  > "/root/backups/user-traffic-2.24.3-$(date +%Y%m%d-%H%M%S).dump"
```

## Update Path (no server upload)

1. Push `feat/model-guard`; CI builds and pushes `:2.25.0`/`:latest` and creates Release `v2.25.0`.
2. The server's built-in check reads `Ericzhouyihe/sub2api-codex-guard` releases.
3. **Export `user_traffic_events` / `user_traffic_hourly` first if they are needed.**
4. The administrator clicks “立即更新镜像”; Watchtower pulls `:latest` and recreates `sub2api`.
5. `WATCHTOWER_CLEANUP=true` removes the previous image. No SSH/SCP, binary upload, local backup or
   rollback data directory is used.

## Rollback Path

- Previous image remains published as `ghcr.io/ericzhouyihe/sub2api-codex-guard:2.24.3`
  (`sha256:7812c3ed...`), verified resolvable in GHCR after the 2.25.0 publish.
- To roll back, pin the compose image to `:2.24.3` and recreate `sub2api`:
  ```bash
  sed -i -E "s#image: ghcr.io/ericzhouyihe/sub2api-codex-guard:.*#image: ghcr.io/ericzhouyihe/sub2api-codex-guard:2.24.3#" docker-compose.yml
  docker compose up -d sub2api
  ```
- Docker mode has no in-page rollback (`DOCKER_UPDATE_UNSUPPORTED`) and creates no local data
  snapshot. Watchtower cleanup means the old image is not kept on the server.
- An image rollback does not reverse the 2.25.0 migrations: 394–398 stay in place, and
  `user_traffic_events` / `user_traffic_hourly` are gone. This rollback was not exercised: 2.24.3
  code still references both tables (traffic recording there is asynchronous, so errors are expected
  in logs rather than on requests), and the「用户流量」page would fail. Restore from the pre-update
  export if those records are needed.
