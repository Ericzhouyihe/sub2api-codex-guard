## Data Counts

This release uses the built-in updater path; no server-side baseline, canary or data snapshot is
created. Model Guard data lives in the existing `data/` volume and is not recreated by the image
update.

## Update Path (no server upload)

1. Push `feat/model-guard`; CI builds and pushes `:2.24.2`/`:latest` and creates Release `v2.24.2`.
2. The server's built-in check reads `Ericzhouyihe/sub2api-codex-guard` releases.
3. The administrator clicks “立即更新镜像”; Watchtower pulls `:latest` and recreates `sub2api`.
4. `WATCHTOWER_CLEANUP=true` removes the previous image. No SSH/SCP, binary upload, local backup or
   rollback data directory is used.

## Rollback Path

- Previous image remains published as `ghcr.io/ericzhouyihe/sub2api-codex-guard:2.24.1`.
- To roll back, pin the compose image to `:2.24.1` and recreate `sub2api`:
  ```bash
  sed -i -E "s#image: ghcr.io/ericzhouyihe/sub2api-codex-guard:.*#image: ghcr.io/ericzhouyihe/sub2api-codex-guard:2.24.1#" docker-compose.yml
  docker compose up -d sub2api
  ```
- Docker mode has no in-page rollback (`DOCKER_UPDATE_UNSUPPORTED`) and creates no local data
  snapshot. Watchtower cleanup means the old image is not kept on the server.
- Note: 2.24.2 adds forward-only migration `393`; rolling back the binary leaves the new rollup
  tables in place (old code ignores them), consistent with the project's forward-only policy.
