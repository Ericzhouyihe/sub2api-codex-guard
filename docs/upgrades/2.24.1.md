meets Model Guard's inspection-owned extra keys in three backend files, and restored/added workflow
files this fork intentionally does not use. Resolution:

- `backend/internal/repository/account_repo.go` (`BulkUpdate`): keep both the fork loop that strips
  `codexInspectionOwnedExtraKeys` and the upstream `delete(updates.Extra, service.OAuth429ModelBlocksKey)`.
- `backend/internal/repository/scheduler_cache.go` (scheduler projection key list): keep both
  `service.CodexInspectionBlockedModelsExtraKey` and `service.OAuth429ModelBlocksKey`.
- `backend/internal/service/openai_model_retirement.go` (`supportsOpenAIRequestModel`): adopt the new
  upstream signature `(requestedModel string, requireCompact bool, compactModel ...string)` and its
  `ResolveOAuth429TargetModel` target resolution, then re-insert the fork's
  `account.codexInspectionUpstreamModelBlocked(target)` check against the resolved target.
- Workflows: resolve 10 modify/delete conflicts plus upstream's 4 newly added workflows and the
  restored `.github/workflow-archive/` files by deletion; only `ci.yml`, `docker-image.yml`,
  `security-scan.yml`, `upstream-sync.yml` remain.
- i18n/routes/sidebar merged cleanly; `nav.accountEvaluation` retained, no `nav.harvestFlow` restore.

## Data Counts

## Update Path (no server upload)

1. Push `feat/model-guard`; CI builds and pushes `:2.24.1`/`:latest` and creates Release `v2.24.1`.
2. The server's built-in check reads `Ericzhouyihe/sub2api-codex-guard` releases.
3. The administrator clicks “立即更新镜像”; Watchtower pulls `:latest` and recreates `sub2api`.
4. `WATCHTOWER_CLEANUP=true` removes the previous image. No SSH/SCP, binary upload, local backup or
   rollback data directory is used.

## Rollback Path

- Previous image remains published as `ghcr.io/ericzhouyihe/sub2api-codex-guard:2.23.1`.
- To roll back, pin the compose image to `:2.23.1` and recreate `sub2api`:
  ```bash
  sed -i -E "s#image: ghcr.io/ericzhouyihe/sub2api-codex-guard:.*#image: ghcr.io/ericzhouyihe/sub2api-codex-guard:2.23.1#" docker-compose.yml
  docker compose up -d sub2api
  ```
- Docker mode has no in-page rollback (`DOCKER_UPDATE_UNSUPPORTED`) and creates no local data
  snapshot. Watchtower cleanup means the old image is not kept on the server.
