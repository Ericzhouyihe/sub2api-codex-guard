## Data-Clearing Migration — Read Before Updating

上游移除「请求耗时明细」和「连接诊断」，`backend/migrations/400_drop_request_diagnostics.sql`
在新镜像启动时执行：

```sql
-- Per-request diagnostics have been retired. Billing and usage records are independent.
DROP TABLE IF EXISTS request_timing_details, request_connection_traces;
```

- 这是**不可逆删表**：回退镜像不会恢复这两张表，内置更新通道也不建快照。
- 只会删除诊断元数据；`usage_logs`、计费记录和账号数据不受影响。
- **Model Guard 不受影响。** 巡检数据在 `data/` 卷、`codex_eval_inspection_*` 设置和
  `accounts.extra` 的 `codex_eval_inspection_blocked_models` 键，迁移不碰这些对象。
- 生产若仍在 2.25.0 或更早，还会连带执行 2.25.3 的 `399_remove_oauth_429_model_blocks.sql`
  （清除账号里的废弃屏蔽键）和 2.25.0 的 `398_drop_user_traffic.sql`（删 `user_traffic_*`）。
  先看 [2.25.3.md](2.25.3.md) 和 [2.25.0.md](2.25.0.md) 的导出步骤。
- 需要留档时在服务器导出（可选）：

```bash
mkdir -p /root/backups
docker exec -i sub2api-postgres psql -U sub2api -d sub2api -Atc \
  "select json_agg(row_to_json(t)) from (select * from request_connection_traces) t;" \
  > "/root/backups/request-connection-traces-2.25.3-$(date +%Y%m%d-%H%M%S).json"
```

> 以上导出命令本次没有在服务器上演练（开发机不执行远程命令）。
